CSS-анимации vs Canvas

Одна игра — два подхода. Разбираем, чем отличается Стартовая версия от официальной и когда что выбирать.

Сравнение по критериям

Критерий Стартовая (CSS) Продвинутая (Canvas)
Рендеринг HTML-элементы (<div>) Один <canvas>, всё рисуется в JS
Движение CSS-анимации или transform Игровой цикл через requestAnimationFrame
Коллизии Сравнение getBoundingClientRect() AABB-коллизии по координатам спрайтов
Спрайты Отдельные background-image Спрайт-атлас, drawImage с обрезкой
Анимация персонажа CSS @keyframes Покадровая смена кадров в спрайт-атласе
Точность Ограничена CSS, зависит от браузера Пиксельная, полный контроль
Производительность Хорошая при малом числе элементов Стабильная при любом количестве объектов
Порог входа Низкий: HTML + CSS + чуть JS Средний: нужно понимать canvas API
Где применять Простые игры, лендинги, анимации UI Игры, редакторы, визуализации, графика

Плюсы и минусы

Стартовая

  • Простой и понятный код
  • Легко читать и редактировать
  • Не нужны знания canvas
  • Быстро запускается
  • Сложно масштабировать
  • Неточные коллизии на разных экранах
  • Анимации зависят от браузера

Продвинутая

  • Полный контроль над графикой
  • Точные коллизии
  • Масштабируется на много объектов
  • Единый игровой цикл
  • Сложнее для новичка
  • Нужно разбираться в canvas API
  • Больше кода

Одна задача — два решения

Стартовая: ПРЫЖОК
// Добавляем класс .jump на 600 мс
function jump() {
    dino.classList.add('jump');
    setTimeout(() => {
        dino.classList.remove('jump');
    }, 600);
}

/* CSS-анимация */
@keyframes jump {
    0%   { bottom: 0; }
    50%  { bottom: 95px; }
    100% { bottom: 0; }
}
Продвинутая: ПРЫЖОК
// Старт прыжка задаёт скорость
startJump: function() {
    if (!this.jumping) {
        this.jumpVelocity =
            this.config.INIITAL_JUMP_VELOCITY;
        this.jumping = true;
    }
}

// Каждый кадр — гравитация
updateJump: function(deltaTime) {
    this.yPos += this.jumpVelocity * frames;

        this.config.GRAVITY * frames;
}

Продвинутая: ДВИЖЕНИЕ
// Препятствие само себя двигает
update: function(deltaTime, speed) {
    if (!this.remove) {
        this.xPos -= Math.floor(

Продвинутая: КОЛЛИЗИЯ
// AABB по координатам спрайтов
function boxCompare(tRexBox, obstacleBox) {
    return (
        tRexBox.x <
            obstacleBox.x + obstacleBox.width &&
        tRexBox.x + tRexBox.width >
            obstacleBox.x &&
        tRexBox.y <
            obstacleBox.y + obstacleBox.height &&
        tRexBox.y + tRexBox.height >
            obstacleBox.y
    );
}

Что выбрать?

CSS-подход хорош для простых игр и быстрых прототипов: меньше кода, легче читать, не нужно знать canvas API. Идеально, если игра — это 2–3 объекта и минимум логики.

Canvas-подход нужен, когда объектов много, важна точность (коллизии, физика, спрайтовая анимация) или нужна графика, которую CSS не потянет. Это «взрослый» путь для настоящих игр.

Наш проект показывает оба: сначала разбираем простой вариант, потом смотрим, как то же самое делает Chromium. Так лучше понимаешь, что именно даёт canvas.
